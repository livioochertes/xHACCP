---
name: Promotional banner QR assets
description: Quality requirements for marketing banners used as homepage image slides.
---

For promotional banners that include exact text or a QR code, use image generation only for background imagery. Render copy as deterministic SVG/vector text and generate the QR from the confirmed destination URL. Export at the homepage hero's aspect ratio and keep the rendered hero at its fixed base height; use contain rather than cropping or stretching the full banner. If the fixed frame leaves space around it, use a clean backdrop sampled from the banner's edge color rather than a blurred duplicate. For an existing campaign cover adapted to the homepage, preserve its arrangement and extend only its background to fill extra Hero area instead of reflowing or cropping its content. For a fluid-width, fixed-height Hero, derive the asset ratio from the actual target viewport in CSS pixels; matching height alone can still leave top/bottom bars with `object-contain`. Account for screenshot scale when converting raster dimensions to CSS dimensions.

When a desktop campaign cover is too panoramic to remain legible on phones, provide an optional mobile-specific asset and select it only at the mobile breakpoint; keep the desktop art intact and use `contain` so QR/text is not cropped. Aim the mobile artwork at the mobile Hero ratio instead of reusing the panoramic file.

Store finished homepage banners without passing them through the product-image optimizer. Keep the original file format, dimensions, and bytes on admin upload so vector-rendered text and QR codes are not softened by downscaling and JPEG recompression.

**Why:** Generated raster text can be illegible and AI-drawn QR patterns are not dependable. Product-image compression and an oversized hero frame both undermine a cover that is otherwise sharp and correctly composed. A blurred underlay can make the side areas look messy; matching the edge color removes the black bars without cropping or stretching the artwork. A 1920-pixel export displayed around 960 CSS pixels halves its typography too, so microcopy needs to be sized for the rendered width. Matching only the fixed height is insufficient: a 1920×410 image shown with `object-contain` inside a narrower 1683×410 Hero leaves empty bands above and below. When an existing campaign cover is already approved, reflowing its elements changes the intended composition; background extension keeps the approved copy, artwork, and QR in place.

**How to apply:** Confirm the QR target from the campaign owner or an existing verified code, compose the QR and readable copy over the design, measure the Hero's CSS width and fixed height at the target viewport (accounting for screenshot/device scale), derive the matching aspect ratio, extend only the side background, inspect it at that width, check export dimensions and scanability, and use a dedicated original-preserving upload path for homepage banners. For multiple artwork variants, pair each QR crop with its own source art; code patterns and crop positions can differ.
